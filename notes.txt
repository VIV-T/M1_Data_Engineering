Run a script.py inside a container launch by Airflow :
    ### Tips :
        - every modification on the script.py needs to be updated by a docker-compose build of the container of this script (cf. container scrapper with run_scrapper.py)

        - To debug python scripts launched in additional containers, follow these instructions : (VS Code)
            Assuming the Airflow DAG associated has already fail
            1. cmd :
                docker compose down     (remove the actual container - environement cleaning)

            2. cmd : 
                docker ps -a --filter "ancestor={image_name}" --format "table {{.ID}}\t{{.Image}}\t{{.Status}}"
            3. Copy the id of the container returned by the previous cmd as 'container_id'
            4. cmd :
                docker logs -f container_id
            => You will have all the logs you have setted + the python Traceback in case of failure in the terminal.

            5. After debugging your python scripts, you must execute these cmd to apply the modifications and run the DAG again :
                docker compose build 'name_of_the_service'      (ex : scrapper - it contains my python script)
                docker compose up -d    (normal launch of docker)

### 18/11 - 19/11
Volume management modification : to handle multi container writting
Main issue : 
    The volume was mounted each time at the building of each container (and the file were writted or copied into it during the building phase)
    But the thing was, when you mount a volume, it erased the previous content in it.
    Let's take an example :
        When I mount the volume on the first service : 'scrapper', the the img is built and the dockerfile is executed.
        Inside this dockerfile, I copy the 'scrapping_data' folder into the volume as 'scrapping_data'

        Then when I mount the volume on the 2nd service known as 'test', the 'scrapping_data' folder is erased and 
        the volume content is now depending of what I'm doing in the dockerfile of this 2nd service.

Solution : 
    Mount the same emty volume on each services.
    The files are copied in the running app in dedicated folders. (ex: /app/scrapping_data)
            => /!\ important to be able to access to those files/folder from the exec environement (ex : in he DockerOperator, to access to the python file to execute)
    Then instead of executing python script with a CMD line in the dockerfile, we execute when needed = with the Airflow DockerOperator.
    The scripts are accountable of the copy and the write of mandatory / necessary files in the shared named volume.
